QQ 邮箱通道配置

授权码获取路径：QQ邮箱 → 设置 → 账户 → 开启「IMAP/SMTP 服务」→ 生成授权码。
注意：必须使用授权码，不能用 QQ 登录密码。未配置时系统不发信，但审查流程完全不受影响。
安全：发件邮箱、SMTP 授权码、收件邮箱均加密存储（scrypt 派生 + HMAC-SHA256 认证加密， 密文落盘 data/mail_secret.json，主密钥单独存放且已被 git 忽略）；页面与接口只回显掩码，明文不下发浏览器。

常见问题

支持哪些合同格式？

Word（.docx）、PDF（.pdf）、扫描件图片（.png / .jpg）。图片走 OCR 识别：本机装有 Tesseract（含中文包）时用真实 OCR，未安装时自动降级为模拟识别并在任务里明确标注，不会静默出错。

审查结论是怎么得出的？可信吗？

两层：① 规则引擎——按预置规则做确定性判定（关键词 / 正则 / 条款缺失），每条规则都标注了法律依据；② 大模型语义研判——补充规则覆盖不到的语义风险，并为每条风险生成可落地的修改建议。没配置大模型时①照常工作，系统完全可用。

问「这条风险凭什么」时，依据在哪看？

工作台的风险卡片上直接展示 法律依据（如《民法典》第五百零九条），规则页每条规则也单独列出。导出的 MD / PDF 报告里同样包含。

三个角色分别能做什么？

系统管理员 张三：规则管理、监控告警、批量操作；业务经办人 李四：上传合同、查看风险、导出报告；法务审查人 王五：核对原文、编辑/采纳建议、写批注、写回审批意见。未选角色时为演示模式（全部放开）。

数据安全吗？

任务与解析全部在本地内存完成；只有在启用大模型时，才会把条款文本发送给你所配置的模型服务商（用于语义研判与建议生成）。邮件通知只发送失败摘要，不含合同全文。

多个合同能一起审吗？

可以。后台默认支持 4 份并发审查（可用环境变量 REVIEW_CONCURRENCY 调整），多份合同同时上传会并行推进，不用排队等前一份审完。
